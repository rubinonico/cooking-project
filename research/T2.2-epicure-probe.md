## Verdict

**Useful. Not for what the plan assumed.**

| Role | Verdict | Evidence |
|---|---|---|
| **Q1 second axis** — per-cuisine position of an ingredient | **Yes, genuinely new** | `cultural_profile` returns a cosine per cuisine direction *plus that cuisine's p10/p90*, so a score is interpretable relative to its own distribution |
| **T2.2 vocabulary bridge** | **Yes — 39/40 resolve** | Flavor Bible entry names map onto Epicure's vocabulary almost completely (below) |
| **Sanity-checking a pairing claim** | **Yes, calibrated** | `pairing_score` returns a percentile band against the whole pair distribution, not a naked cosine |
| **Coverage denominator** | **No** | Its 8 macro-regions ≠ the Flavor Bible's ~40 cuisine entries. Two different partitions, both needed (D2) |
| **Food safety** | **Never** | Its own README disclaims it. Unchanged (D1) |

## 1. Vocabulary overlap — 39/40

40 Flavor Bible entry names, resolved against Epicure's 1,790-ingredient vocabulary:

- **28 resolved as typed.** 12 failed — and **11 of those 12 were plural or hyphen artefacts**
  (`ALMONDS`→`almond`, `TOMATOES`→`tomato`, `SHALLOTS`→`shallot`, `CAPERS`→`caper`,
  `ANCHOVIES`→`anchovy`, `MUSHROOMS`→`mushroom`, `SCALLIONS`→`scallion`, `CAYENNE`→`cayenne_pepper`,
  `SEA SALT`→`salt`, `SESAME`→`sesame_seed`, `PEPPER`→`black_pepper`).
- **1 genuinely absent:** `cilantro` (it has `coriander`, which resolved).

**39/40 = 97.5%.** Normalisation needed: lowercase, singularise, `snake_case`, and a small alias map
(`cilantro`→`coriander`). That alias map is required work, not a nuisance — record it as such.

Unresolved names come back as a **plain-text error string**, not a JSON error object:
`"Error executing tool neighbors: Could not resolve ingredient 'tomatoes'"`. A client must handle both
response shapes or it crashes on the misses. Measured.

## 3. `pairing_score` is calibrated, and that is the useful part

Returns `{pairing_score, percentile_label, all_pairs_range{p10,p25,median,p75,p90}}`.

| Pair | Score | Label | Book says |
|---|---|---|---|
| tomato + basil | 0.271 | very high (≥p90) | a classic |
| lamb + mint | 0.250 | very high (≥p90) | a classic |
| miso + soy sauce | 0.297 | very high (≥p90) | same family |
| chicken + rosemary | 0.151 | high | endorsed |
| lamb + sardine | 0.099 | moderate | no strong claim |
| **tomato + chocolate** | **0.044** | **low** | not a pairing |

**6/6 agree with the book's own tiering.** The percentile band is what makes it usable: a raw cosine of
0.044 means nothing, "low, where the median pair is 0.092" means something. Report the band, never the
number alone.

## 4. `cultural_profile` — the genuinely new axis

`miso` → Japanese **0.323** (its p90 is 0.190, so this is *above* the 90th percentile — extreme),
East_Asian 0.163, Southeast_Asian 0.043, then negative for the other five. Interpretable without
knowing anything about the embedding.

This is the axis the Flavor Bible cannot give: **it does not quantify cuisine affinity at all**, it lists
cuisines an ingredient appears in. So `cultural_profile` supplies a *second, independent* reading of
cuisine fit — exactly what Q1 needs to avoid a single-source coverage claim.

## Pitfalls measured (both are real, both cost time)

1. **`Python-urllib/3.11` as a User-Agent → HTTP 403 Forbidden.** Not auth — the endpoint is anonymous.
   It is a UA filter (Cloudflare-style). `curl`'s default UA passes; Python's does not. Any client must
   send a real UA. This is why the first two attempts failed before a single tool ran.
2. **A tool-level failure returns plain text, not a JSON error.** `{"error": ...}` is *not* the shape.
   Code that assumes JSON on every call breaks on the first unresolvable ingredient.

Client: `tools/epicure.py` (handshake + call, both pitfalls handled).

## What this changes in the plan

- **T2.2 stays open** but its risk is gone: the bridge is feasible and the rate is high. Add the alias
  map (`cilantro`→`coriander` + singularisation) as explicit work inside it.
- **T2.1 gains a second axis.** Coverage may now be reported as *Flavor Bible cuisines listed* **and**
  *Epicure cuisine-affinity above that cuisine's p90*. Two independent readings of the same claim —
  which is what D6 demands and what a single-source answer could not provide.
- **D11 amended:** tools are not needed to use it; `tools/epicure.py` works today.
